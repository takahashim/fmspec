# 性能

仕様書§13の測定項目のうち、状態/秒、遷移/秒、ピークRSS、探索と証明書の検査の時間を測る。
性能目標値は、実測を重ねてから決める。

## 測り方

```sh
cargo build --release
ruby -Ilib bench/run.rb              # 各モデルを3回検査し、最小の時間を表にする
ruby -Ilib bench/run.rb --repeat 5 --fmspec PATH/TO/fmspec
ruby -Ilib bench/models.rb DIR       # モデルのIRを DIR に書く
```

モデルは `bench/models.rb` にあり、仕様書§13が挙げる種類に合わせてある。

| モデル | 内容 |
|---|---|
| `counters` | 小規模カウンタ。3つの整数を独立に増減する |
| `registers` | 引数のある操作。5つの整数に 0..9 の値を書く。状態ごとの遷移が多い |
| `orders` | 複数レコード。注文の状態を Map に持つ |
| `sets` | 集合。2つの Set の間で要素を移す |
| `processes` | 並行するプロセス。4つのプロセスがロックなしで読み書きする |

`search_ms` は探索器（`fmspec-search`）、`gate_ms` は判定ゲートが証明書を検査する時間である。
判定ゲートは探索器の記録した辺を使わず、各状態の後続を再計算するので（仕様書§14.2）、`gate_ms` は `search_ms` と同じ程度になる。
ピークRSSは、Linux の `/proc/PID/status` の `VmHWM` を読んで得る。

## 測定結果

4コアのLinuxのコンテナで、`cargo build --release` のビルドを測った。時間は3回のうち最小で、ミリ秒。
「前」は性能改善の前のコミット `8798990`。

| モデル | 状態 | 遷移 | 探索（前→後） | 証明書の検査（前→後） | ピークRSS MB（前→後） |
|---|---|---|---|---|---|
| `counters` | 512000 | 3033600 | 966 → 752 | 752 → 697 | 122.5 → 72.5 |
| `registers` | 100000 | 5000000 | 1324 → 841 | 1376 → 1288 | 34.2 → 20.8 |
| `orders` | 78125 | 437500 | 1418 → 1110 | 1363 → 1053 | 39.6 → 23.9 |
| `sets` | 59049 | 787320 | 1228 → 835 | 1234 → 929 | 41.5 → 21.9 |
| `processes` | 755 | 1156 | 0.9 → 0.7 | 0.6 → 0.4 | 2.1 → 3.1 |

`processes` は小さく、時間とRSSは誤差の範囲である。

## 行った改善

- **局所変数の列を使い回す**（`fmspec-core`、検証済み）。
  下ろした式は、失敗しうる部分式を `let` で束縛する。
  以前は `let` と量化のたびに局所変数の列を丸ごとコピーしていたが、列の末尾に積んで評価し、降ろして元に戻すようにした。
  `eval_in` の事後条件に、列が呼び出し前と同じに戻ることを加えてある。
  遷移の列挙（`enumerate`）は、作業用の列を1つ確保し、すべての引数の guard、更新、出力の評価で使い回す。
- **列のコピーで容量を先に確保する**（`copy_vec`）。
- **訪問済み集合**（`fmspec-search`、未検証）。
  状態を節点の列にだけ置き、ハッシュ表には節点の添字を入れる。状態を2か所に持たないので、保持するメモリが減る。
  ハッシュには FxHash を使う。同じハッシュ値の状態は符号化列の一致で確かめ、ハッシュ値だけで状態を同一視しない。

## 残っている課題

- 時間の大半は、下ろした式の評価（`eval_in`）と、遷移ごとの状態と引数の列の確保である。
  複合型の式は、スロットごとの式と正規形の判定に下ろすので、式が大きい。下ろし方の改善は、`preserve.rs` の証明の更新を伴う。
- 証明書の検査は探索と同じ量の計算をする。証明書の圧縮や、検査の並列化は後続の課題である（仕様書§14.2）。
- 状態の圧縮、構造共有、バイトコードVM、並列探索、Partial Order Reduction は未着手である（仕様書§13）。
